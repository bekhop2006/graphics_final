# Astana Night 3D

An interactive model of Nurzhol Boulevard in Astana. Start at the night overview, fly to a building, then click it to see its selection highlight. All building shapes, surface patterns and stars are generated by the program. The scene uses simplified distances and proportions.

## Build and run on Windows

Extract the whole archive. For the example below, select `C:\CG` as the extraction directory. Open **MSYS2 UCRT64** from the Start menu.

1. `echo "$MSYSTEM"` prints the name of the active MSYS2 environment. It should print `UCRT64`.
2. `pacman -S --needed make mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-freeglut mingw-w64-ucrt-x86_64-glew` installs GNU Make, the C++ compiler and the two OpenGL libraries. Skip this step if they are already installed.
3. `cd /c/CG/AstanaNight3D` opens the project directory that contains the Makefile. If you extracted elsewhere, use that directory instead.
4. `make` compiles the C++ sources and links the Windows executable. Running it again rebuilds changed sources and headers.
5. `./astana3d.exe` opens the live model. Keep the program in the UCRT64 environment so Windows can find its runtime libraries.

The program requires a graphics driver with an OpenGL 3.3 core context. The GLSL shaders are embedded in the C++ source. The screenshots are examples, and the program does not load them.

## Build and run on macOS

1. `brew install glfw glew` installs the window library and the OpenGL loader.
2. `make` compiles the project. On macOS, `src/glut_glfw.hpp` provides the freeglut calls on top of GLFW, because XQuartz freeglut cannot create an OpenGL 3.3 core context.
3. `./astana3d` opens the live model.

## How the scene is drawn

The CPU builds one triangle list. Each vertex stores a position, a normal, a base color, UV coordinates, a material index and an object ID. The visible pass draws a procedural sky and then the depth-tested mesh. A separate integer framebuffer stores group IDs for picking. Supersampling renders the visible pass at twice the width and height, then reduces it to the output size with a linear blit. The picking buffer stays at the window size.

The service roads contain four car body styles. The hood and trunk are gently raised at the centre. Their edges meet the fenders and bumpers along shared vertices. The compact has oval headlamps, and the SUV has a grille and two levels of lights. The mesh also includes wheel openings, window pillars, tyres, rims and mirrors.

Press **C** to inspect one example of each style. These camera views use a 33-degree vertical field of view and a longer viewing distance so the near bumper stays in proportion. Drag with the left mouse button to see the other end. Press **N** to compare the paint and glass in daylight and at night.

At startup, the renderer captures the city in six directions from a point near the fastback. It repeats this for daytime and nighttime to build two reflection cubemaps. The car materials blend the maps as the sky changes. The same maps are shared by the fleet, so reflections away from the capture point are approximate.

## Capture and reproduce

- `./astana3d.exe --help` prints the capture options and controls.
- `./astana3d.exe --shots capture --width 1280 --height 720` saves the fixed views as binary PPM images and writes the renderer and picking results to `capture/capture.log`. The program creates the last directory component.
- `./astana3d.exe --tour frames --width 1280 --height 720 --fps 18` records the 48-second guided tour as numbered PPM images. Allow about 2.4 GB for this sequence. The tour uses the same renderer and ID lookup as the interactive application.

## Linux with a virtual display

On Debian with administrator access, `sudo apt-get install g++ make freeglut3-dev libglew-dev libgl1-mesa-dri xvfb xauth` installs the compiler, libraries, software renderer and virtual display tools.

From the project directory, `make` builds the Linux executable. The command `LIBGL_ALWAYS_SOFTWARE=1 xvfb-run -a -s "-screen 0 1280x720x24" ./astana3d --shots capture --width 1280 --height 720` starts a temporary X server, chooses Mesa software rendering and saves frames using OpenGL pixel readback. Open `capture/capture.log` to see the actual context, sample scale and object IDs on your machine.
